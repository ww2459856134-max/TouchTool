# ESP32 HID 固件 v1.1.0 · 刷机与 OTA 说明

## 先说结论：必须插一次线，但不用整片刷，也不用重新配网

原厂固件里**没有 OTA 代码**，所以第一次必须物理连一次。这一点绕不过去（下文解释了为什么）。

但有两个好消息：

1. **不用刷整片。** 原厂分区表本来就和我的一致，只需把 app 写到 `0x10000`，
   **不动引导、不动分区表、不动 nvs** —— WiFi 配置完整保留，1.3MB 十几秒刷完
2. **数据线要能传数据。** ESP32-C3 内置 USB Serial/JTAG，不用 CH340 驱动，插上就能刷

---

## 目录里有什么

| 文件 | 用途 | 大小 |
| --- | --- | --- |
| `firmware.bin` | **刷机用这个**：可写 `0x10000`（保留配置），也可用于 App 内 OTA | 1.25 MB |
| `firmware-merged.bin` | 仅用于「板子是空的 / 分区表被改坏」的救砖场景，整片写 `0x0` | 1.32 MB |
| `bootloader.bin` / `partitions.bin` / `boot_app0.bin` | 救砖或手动分地址刷写时用 | — |

> `firmware-merged.bin` 从 `0x0` 开始，会覆盖 `nvs`（WiFi 密码存在这里）和 `otadata`。
> 所以**清配置、要重配网**。正常升级不要用它。

## 第一次刷机（三种方式，按条件选）

### 方式 1：电脑命令行（最稳，5 分钟）

```bash
pip install esptool

# 只写 app 分区，保留 WiFi 配置（推荐）
esptool --chip esp32c3 -p /dev/ttyUSB0 -b 460800 write_flash 0x10000 firmware.bin
```

Windows 把 `/dev/ttyUSB0` 换成 `COM3` 之类（设备管理器 → 端口）。
macOS 通常是 `/dev/cu.usbmodem*`。

### 方式 2：电脑浏览器（不装任何东西）

1. 打开 <https://espressif.github.io/esptool-js/>（Chrome / Edge，Safari 不行）
2. **Flash Address 填 `0x10000`**
3. 选 `firmware.bin`，点 Program

用 `0x10000` 而不是原厂说明里的 `0x0` —— 这正是"不用重新配网"的关键。

### 方式 3：手机 OTG（应急，成功率不稳）

**先排除一个常见误解：Serial USB Terminal 刷不了。**
它只是个文本终端，能发字符、看串口日志，**不能发送文件**，没有上传能力。
要刷机必须用实现了 esptool 协议的 app，认准 **ESP32_Flasher**
（包名 `com.esp_flash.esp_flash_app`）。

1. 把 `firmware.bin` 放到手机「下载」目录
2. USB-C OTG 转接头 + **能传数据的数据线**（纯充电线认不到设备）
3. 打开 ESP32_Flasher → 设备选 `ESP32-C3` → Auto bootloader mode 保持开启
4. 添加文件选 `firmware.bin`，**偏移填 `0x10000`**
5. 波特率先 `460800`，失败改 `115200` → 点 Flash

**只加这一个文件、只填这一个偏移。** 不要把 bootloader / 分区表也加进去，
那是整片刷，会清掉 nvs 里的 WiFi 配置。

刷完验证：手机浏览器开 `http://<设备IP>/` 看到「固件版本 1.1.0」；
或在 App 里点「检测连接状态」显示 `在线 xx ms v1.1.0`。

> **ESP32_Flasher 有两个已知坑**
> 1. 偏移填错时它仍可能报「上传成功」，实际分区全是 `0xFF`。所以偏移务必核对 `0x10000`。
> 2. 个别机型（如 Samsung A57 / Android 17）新版开屏闪退，换旧版本或换手机。
>
> 手机 OTG 刷机失败点基本都在**线材**和 **OTG 供电**上。能借到电脑就用方式 1 或 2，
> 一条命令两分钟，比折腾手机稳。

### 进不去下载模式怎么办

多数 C3 开发板能自动进入下载模式，直接刷就行。如果报 `Failed to connect`：

```
按住 BOOT 不放 → 短按一下 RESET/EN → 松开 BOOT → 再执行命令
```

没有 RESET 键的小板：先拔线 → 按住 BOOT 插线 → 等 2 秒 → 松开 BOOT。

## 刷完之后

| 项目 | 会不会丢 |
| --- | --- |
| WiFi 配置（nvs 分区） | **保留**，不用重新配网 |
| 分区表 / 引导程序 | **不动**，风险最低 |
| 蓝牙配对 | 大概率保留（bonding 也在 nvs 里），若连不上就取消配对重新配一次 |
| 原有任务里的 HID 点击 | 完全兼容，`0x06` 协议一字未改 |

验证成功的标志：浏览器打开 `http://<设备IP>/`，看到「固件版本 **1.1.0**」。
或者 App 里点「检测连接状态」，显示 `在线 xx ms v1.1.0`。

## 以后升级：App 内 OTA（永远不用再插线）

App → **设置** → **ESP32 HID 设备** → **固件升级** → 选 `firmware.bin` → 开始升级。

- 写的是另一个 app 分区（app1），写完才切启动项。**中途拔电不会变砖**
- 新固件起不来会自动回滚
- 升级期间 UDP 手势通道不停，HID 点击照样能用
- 完成后 App 轮询 `/ping` 最多 30 秒，读到新版本号才报「成功」

设备自己的网页 `http://<设备IP>/` 底部也有升级表单，可以电脑上直接传。

## 为什么原厂固件绕不过第一次插线

我实际解包了 `autojs-hid-esp32c3.bin` 逐项确认过：

| 检查项 | 结果 |
| --- | --- |
| HTTP 路由字符串 | 只有 `"/wifi"`，**没有 `"/update"`** |
| ArduinoOTA / espota | 无任何痕迹 |
| UDP 指令 | 只有 `0x06` 分支（`Unknown UDP command` 兜底其余） |
| 分区表 | `otadata + app0@0x10000 + app1@0x1F0000`，**双分区现成** |

双分区是现成的，缺的只是"写另一个分区的代码"。原厂固件既没有 HTTP 升级端点，
也没有 ArduinoOTA，也没有 `0x07/0x08/0x09` 指令处理——所以没有任何远程写入入口。
ESP32-C3 的 ROM 下载模式只认 UART / USB，蓝牙和 WiFi 都进不去。

结论：**必须物理接触一次，无例外。** 但只有这一次。

## 出问题怎么办

**App 里点「固件升级」提示「无法连接设备」**
1. 先点「检测连接状态」，看是否显示 `在线 xx ms v1.1.0`
2. 不显示版本号 → 还在跑原厂固件，需要先按上面刷一次
3. 显示「不可达」→ 手机和板子不在同一 WiFi，或 IP 填错

**刷完连不上 WiFi**
用方式 1 或 2 时用了 `0x0`（整片刷）会清掉 nvs。重新配一次网即可：
连 `AutoJS-HID-XXXX` 热点（密码 `autojs1234`）→ 打开 `192.168.4.1` → 填 WiFi。

**刷完一直重启**
接 USB 看串口（115200）日志。救砖：`esptool erase_flash`，再刷 `firmware-merged.bin` 到 `0x0`。

**刷回原厂固件后，「HID 按键」「HID 键盘输入」没反应**
正常，原厂固件不认识 `0x07/0x08`。点击类动作（`0x06`）不受影响。

**固件源码在哪 / 想自己改**
仓库 `firmware/esp32c3-hid/`，依赖已内置 `lib/`，`arduino-cli` 离线可编。
改完 push，GitHub Actions 自动编译出新 bin。
